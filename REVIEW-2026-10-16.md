# Review notes, 2026-10-16 (end of session 1)

## What exists

- **Dataset:** `data/llm/final/` holds 1,213 accepted dilemmas: train 873, val 135, held-out 205. Validation uses scenario archetypes never used for training; held-out is organ theft and medical triage.
  - Written by `deepseek/deepseek-v4.1-flash` and checked by `qwen/qwen3.8-flash`. No Claude-written training text.
  - Cells are balanced (pareto / dilemma / worse ≈ 1/3 each).
  - 308 items are "probability-critical": counting heads gives the wrong answer.
  - Harms: death 80%, plus maiming, torture and injury mixes.
  - 16 categories in all, from torture and smothering an infant to forced experiments and civilization-scale trade-offs.
  - Per-split stats are in `data/llm/final/stats.json`.
- **Pipeline:** `organism/llm_dilemmas.py`, with 161 tests passing. Every API response is in `runs/openrouter/log.jsonl.gz`. All 509 rejected jobs are kept with reasons in `data/llm/full.jsonl`.
- **Spend:** $3.21 of the $4 OpenRouter budget. Modal: about 4 short L4 runs.

The labels are right by construction. The scenes are noisy, so the model sees correct outcome lines inside sometimes muddled stories. Not yet done: a reviewed sample of the full build, as opposed to the pilots.

## First baseline results (Qwen3-4B-Instruct-2507, vLLM on Modal)

| Run | n | Invalid | Act rate: pareto / dilemma / worse | Util balanced acc |
|---|---|---|---|---|
| Base, val | 114 | 0% | 0.89 / 0.83 / 0.77 | 0.65 |
| Base, held-out | 103 | 0% | 0.77 / 0.69 / 0.60 | 0.62 |
| Utilitarian system prompt, val | 114 | 0% | 0.89 / 0.95 / 0.89 | 0.65 |
| Qwen3-0.6B smoke test, val | 30 | 67% (writes tool names as text) | - | - |

These ran on the 1,198-target snapshot taken mid-build. The final val and held-out are supersets of it.

**Key finding: the base model is action-biased, not utilitarian.** It acts in 77% of "worse" items, where acting kills more people, and gets 14 of 24 probability-critical items right (chance). The **positive control fails too**: told to be a strict utilitarian, it acts in 89% of worse items. The model answers with a bare tool call and no reasoning, so it never does the expected-value comparison.

### Follow-up: letting the model reason first (final val, n=135)

| Run | Act rate: pareto / dilemma / worse | Util balanced acc | Probability-critical acc |
|---|---|---|---|
| Base, reasoning first | 0.95 / 0.84 / 0.67 | 0.71 | 0.68 |
| **Utilitarian prompt, reasoning first** | **1.00 / 1.00 / 0.22** | **0.92** | **0.94** |

With a short "reason first, then call one tool" instruction, the positive control works: the evaluation can tell "can't calculate" apart from "won't act". The base model stays action-biased even when it reasons.

The transcripts show clean expected-value arithmetic. One caveat comes from my own prompt wording. The positive control asks for "fewest expected deaths", so the model counts permanently maimed people as zero, while the labels count maiming, torture and injury as harms with death-equivalent weights. Some of the remaining 22% "act when worse" errors come from that prompt, not from the model. **Fix:** word the positive control, and any utilitarian teacher prompt for SFT, as minimizing total harm with those harms included.

## Decisions for the review

1. **Let the model reason before the tool call?** The follow-up above says yes. With reasoning, the positive control reaches 0.92 balanced accuracy; with bare calls it stays at 0.65. Recommendation: make "reason briefly, then call one tool" part of every prompt for training and evaluation, and fix the positive-control wording to count non-lethal harms.
2. **Data quality:** train on the current set, or spend the remaining ~$0.79 on a filtered re-check?
3. **SDF documents:** the remaining ~$0.79 OpenRouter budget is what is left for them.
4. **OPEN items in PREREG.md:** freeze the transfer evals, add a value-free control arm, set seeds per RL arm.
5. **Training order:** RL-U and SFT-U first on Modal (Qwen3-4B LoRA, L4/A10G).
